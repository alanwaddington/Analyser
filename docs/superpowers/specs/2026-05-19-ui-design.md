# UI Design Spec — Analyser
**Date:** 2026-05-19
**Status:** Approved

---

## Overview

Build the full client-side UI for the Analyser app. The app has two modes — Device Comparison and Event Comparison — accessible from a persistent sidebar. All processing runs in the browser; no backend is required for the core UI.

---

## Decisions Made

| Decision | Choice | Reason |
|----------|--------|--------|
| Navigation | Sidebar | File list always visible; mode switch is one click |
| Theme | System default (dark + light) | Follows OS preference; build both |
| Chart layout | Tabbed sections | Charts / Map / Mean-Max / Summary — cleaner than stacked scroll |
| Deployment | Vercel (already configured) | Auto-deploys from GitHub |

---

## File Limits

- Maximum **6 files** per session (enforced by the colour palette — see Theme section)
- If a user attempts to load a 7th file, display a dismissible inline warning ("Maximum 6 files — remove one before adding another") and reject the file without crashing
- CLAUDE.md specifies "at least 5 files in one session" — 6 satisfies this

### Shell
```
┌──────────────┬────────────────────────────────────┐
│   Sidebar    │   Main area                        │
│   (210px)    │   [ Tab bar — hidden until files   │
│              │     are loaded ]                   │
```

### Sidebar (shared across both modes)
- **Logo** — "Analyser" wordmark + tagline
- **Mode nav** — two items: ⚡ Device Comparison, 🏃 Event Comparison. Active item highlighted in mode accent colour (blue for Device, green for Event)
- **File / activity list** — colour-coded dot per file, filename, optional metadata line. In Device mode: device names. In Event mode: date + finish time + "Reference" badge on the reference activity row. The reference row also gets an amber (`#f59e0b`) left border on the row itself, matching the Summary tab treatment, so the reference is visually consistent across the app. In Event mode, each row is **clickable** to set that activity as the reference — rows show a subtle hover state (background tint) to indicate interactivity. In Device mode, rows are not clickable.
- **Add files button** — a compact drag-drop target rendered below the file list. Rendered as a `<label>` element wrapping a hidden `<input type="file" multiple accept=".fit">` — clicking the label triggers the native file picker. Styled with dashed border, label "+ Add files", no icon. Also accepts drag-drop: `dragover`/`drop` events are handled directly on the label. Same `DropZone` component as the empty state, passed `compact={true}`.
- **Footer controls** (both modes):
  - **X-axis toggle** — pill toggle: "Time / Distance". Default: Time. Present in both modes. In Event mode this is additionally labelled "Align by".
  - **Smoothing slider** — 1–60 s, labelled with current value. Present in both modes.

### Main area — empty state (no files loaded)
The tab bar is **hidden**. The main area shows a centred full-size drop zone (see Empty State section).

### Main area — with files loaded
Tab bar is visible at the top. Tabs differ per mode:

| Mode | Tabs |
|------|------|
| Device Comparison | Charts · Map · Mean/Max · Summary |
| Event Comparison | Charts · Map · Segments · Summary |

Active tab underline uses the mode accent colour.

## Routing

```
/          →  Landing / drop zone
/compare   →  Device Comparison mode
/event     →  Event Comparison mode
```

**Source of truth for active mode is the URL route**, not the session store. The store does not hold "active mode".

**`/` redirect behaviour:** `+page.svelte` at `/` uses a Svelte `$effect` with the condition `activities.length >= 1 && !clearing`. When true it calls `goto(...)`, which causes a **route change to `/compare` or `/event`** — the drop zone is not unmounted in-place; it disappears because the route changes and `+page.svelte` is no longer rendered. The "drop zone unmounts" language in the Empty State section refers to this route change, not a reactive conditional within the page.

`lastMode` governs **subsequent** redirects, not the first. On first-ever load `lastMode` defaults to `'compare'`; the redirect always goes to `/compare` until the user explicitly navigates to Event mode. `lastMode` is written in two places:
1. `Sidebar.svelte` mode nav click handlers — clicking "Device Comparison" sets `lastMode = 'compare'`; clicking "Event Comparison" sets `lastMode = 'event'`
2. `+layout.svelte` — on every route change (via `$page.url.pathname`), update `lastMode` only when the path is `/compare` or `/event`. When the path is `/`, do **not** update `lastMode` — leave it at its last value so the next redirect goes to the correct mode.

**Back-navigation clearing:** there are two distinct paths that lead back to `/`:

- **Programmatic removal (user removes all files on `/compare` or `/event`):** the route calls `goto('/')`. By the time `+page.svelte` mounts, `activities` is already empty (`length === 0`). `onMount` sees empty activities, skips the clearing sequence entirely, and the drop zone renders immediately. `clearing` is never set in this path.

- **Browser back button (user presses back after having been redirected from `/` to `/compare`):** SvelteKit re-mounts `+page.svelte`. At this point `activities` is still populated (they were not cleared — the user just navigated back). `onMount` sees `activities.length > 0`, sets `clearing = true`, clears `activities`. A `$effect` watching `activities.length === 0 && clearing === true` then sets `clearing = false`. The redirect `$effect` (`activities.length >= 1 && !clearing`) does not fire because `clearing` is true during the clear. Once `clearing` is false, `activities` is already empty so the redirect condition is no longer met — the drop zone renders normally.

SvelteKit **re-mounts** `+page.svelte` on every navigation to `/` from another route. The clearing mechanism depends on this — if SvelteKit ever transitions without unmounting (e.g. shallow routing in future versions), this mechanism would need revision.

State held in `session.ts`: `activities` (Activity[]), `smoothing` (number, default 10), `xAxisMode` ('time' | 'distance', default 'time'), `referenceIndex` (number, default 0), `clearing` (boolean, default false), `lastMode` ('compare' | 'event', default 'compare'), `activeChannels` (ChannelKey[], default all channels present in loaded activities — initialised when files are loaded, persists across tab changes so toggle state survives switching between Charts / Map / Summary tabs).

Navigating between `/compare` and `/event` preserves all loaded files.

## Empty State

When no files are loaded, the main area shows a centred full-size drop zone (`DropZone` with `compact={false}`):
- Dashed border, large drop icon, primary text "Drop .fit files here", secondary text ".fit supported" (`.tcx` and `.gpx` are listed in CLAUDE.md as "secondary formats to consider" — do not advertise or wire them up until the parser layer explicitly handles them; for v1 accept `.fit` only)
- "Browse files" button as fallback for click-to-open; file picker `accept` filter: `.fit`
- Accepts multiple files in one drop

Once files are loaded the drop zone unmounts, the tab bar appears, and the active route's tab content renders.

**All-files-removed state:** if the user removes all files while on `/compare` or `/event`, the routes reactively watch `activities.length === 0` and call `goto('/')`. The landing page drop zone is shown again. This is the same mechanism as the initial redirect, in reverse.

## Device Comparison Mode

### Charts tab
- **Channel toggle bar** below the tab bar — one pill per channel that is present in **at least one** loaded file (union across all activities). If a channel is missing from some files, those files simply have no series for that channel; the pill is still shown. Pills show the channel colour when active; greyed out with a muted border when inactive. Toggling a pill shows/hides all series for that channel across all charts without reloading. `ChannelToggleBar` receives `channels: ChannelKey[]` as a prop — the parent page derives this union from `session.activities` before passing it in.
- **Chart cards** — one card per active channel, stacked vertically and scrollable
  - Header: channel name + unit on the left; Avg and Max stats on the right, one value per loaded file in that file's colour
  - Body: `TimeSeriesChart` ECharts line chart. **Line styles in Device mode:** file 1 = solid; files 2–6 all use ECharts `lineStyle.type = [6, 3]` (6px dash, 3px gap) — the same dash array for all non-primary files. X-axis: elapsed time or distance per the x-axis toggle (footer). **Lap/split markers:** use the first loaded file's lap structure; if it has no explicit laps, fall back to 1 km distance markers. Apply the same markers to all charts regardless of which file owns each series.
  - Footer: custom HTML legend (not ECharts built-in legend) rendered below the canvas — one row per series showing a coloured line swatch (solid or dashed matching the series style) and the filename. This is a `<div>` outside the ECharts canvas so it can use CSS and respond to theme.
- **Synchronised zoom** — ECharts `connect()` links all chart instances by a shared group ID
- **Hover crosshair** — vertical line across all charts at the hovered x position; tooltip shows all series values at that point
- **Map crosshair sync** — only active when x-axis is **distance**. In time-axis mode the map shows static traces with no hover highlight (there is no reliable 1:1 mapping from elapsed time to GPS position when activities are not time-aligned).

### Map tab
- Leaflet map with OpenStreetMap tiles
- One GPS polyline per loaded file, in that file's colour
- **Chart → map sync (distance mode only):** when the user hovers over any chart, a position marker appears on the map at the GPS coordinate corresponding to the hovered distance value for each activity. The marker moves as the cursor moves along the chart.
- **Map → chart sync:** hovering the map surface does **not** drive the chart crosshair. Map interaction (pan, zoom, click) is independent. Only chart hover drives the map marker.

### Mean/Max tab
- One ECharts line chart: x = duration (log scale, 1 s to activity length), y = best average power
- One series per loaded file, in that file's colour
- Solid line for all series (line style differentiation is not needed here; colour suffices)

### Summary tab
- Table: rows = channels, columns = files
- Cells show Avg / Max / Min for each channel per file
- File column headers use the file's colour dot

## Event Comparison Mode

### Reference activity
The **first file loaded** is automatically set as the reference (`referenceIndex = 0`). The user can change the reference by clicking any activity row in the sidebar — the clicked row receives the "Reference" badge; the previous reference reverts to a normal row. Reference changes take effect immediately on all charts.

**File removal guard:** when a file is removed from the session and it was the current reference, `referenceIndex` resets to `0` (the new first file in the list). If it was not the reference, `referenceIndex` is adjusted to remain pointing at the same activity (decrement by 1 if the removed file's index was lower than `referenceIndex`). If the removed file was the last file (`activities` drops to `0`), the `goto('/')` navigation in `/compare` or `/event` handles the empty state — no separate reset of `referenceIndex` is needed, as it defaults to `0` on any new file load.

### Charts tab
- **Channel toggle bar** — same `ChannelToggleBar` component as Device mode, placed below the tab bar. Controls which metric overlay cards are visible. The Time Delta card is **not** controlled by the toggle — it is always visible.
- **Time Delta card** (pinned at top of scrollable area, always shown)
  - Title: "Time Delta vs Reference" in green accent
  - Subtitle: "Positive = ahead · Negative = behind · aligned by [time/distance]" — updates with x-axis toggle
  - Rendered by `DeltaChart` component. One series per non-reference activity. X-axis: the reference activity's distance or elapsed-time axis, clipped to the length of the shortest activity in the set. Y-axis: cumulative seconds ahead of (positive) or behind (negative) the reference. Zero line drawn. Colour per activity. Custom HTML legend (same pattern as `TimeSeriesChart`) shows filename, net delta, and finish time.
- **Metric overlay cards** below — one per active channel (`TimeSeriesChart`). All activities overlaid on the shared x-axis. **Line styles in Event mode:** reference activity = dashed `[6,3]`, non-reference activities = solid. `TimeSeriesChart` receives `referenceIndex` as a prop; the component applies the dash to `series[referenceIndex]` and solid to all others.
- **Lap/km markers** — use the reference activity's lap structure ("Lap 1", "Lap 2", …). If the reference has no explicit laps (or only one lap covering the full activity), fall back to 1 km distance markers ("1km", "2km", …). Markers appear as vertical dashed lines on all charts.
- Synchronised zoom (ECharts `connect()`)
- Hover crosshair across all charts simultaneously
- **Map crosshair sync:** chart → map position marker is active only when x-axis is **distance**. When x-axis is **time**, the map shows static traces with no hover marker — same fallback as Device mode. Map interaction never drives chart crosshairs in either mode.

### Map tab
- Leaflet map with all GPS traces overlaid, one colour per activity
- Reference trace rendered as a dashed polyline; non-reference traces solid. Leaflet's default `L.polyline` does not support dashes — use Leaflet's SVG renderer with a custom `className` and apply `stroke-dasharray: 8 6` via CSS to the reference polyline's SVG path element. Non-reference polylines use the default solid stroke.

### Segments tab
- Rendered by `SegmentChart`. Bar chart using same segment boundaries as the lap/km markers (reference laps, or 1 km fallback).
- X-axis labels: "Lap 1", "Lap 2", … when using lap structure; "0–1km", "1–2km", … when using km fallback
- The **reference activity is not represented** — it is the baseline (zero). One group of bars per segment; one bar per non-reference activity in that activity's file colour
- **Segment time delta computation:** for each segment, find the elapsed time the reference activity spent in that segment (entry distance to exit distance, interpolated from records). Do the same for each non-reference activity. Bar value = reference segment time − candidate segment time (positive = candidate was faster in that segment). This sign convention matches the Time Delta card — positive always means the candidate is ahead/faster than the reference.
- Bars above zero = faster than reference: bar fill uses a green tint — **dark theme:** `#166534`, **light theme:** `#bbf7d0`
- Bars below zero = slower: red tint — **dark theme:** `#991b1b`, **light theme:** `#fecaca`
- Y-axis label: `'Δ (s)'`

### Summary tab
- Table: rows = activities (reference first), fixed columns:

| Column | Value | Source field |
|--------|-------|-------------|
| Activity | Filename | `activity.filename` |
| Date | Start date formatted DD MMM YYYY | `activity.startTime` |
| Total Time | mm:ss | `activity.totalElapsedTime` |
| Distance | km to 2dp | `activity.totalDistance` |
| Avg HR | bpm, if available | avg of `heartRate` records |
| Max HR | bpm, if available | max of `heartRate` records |
| Avg Pace | min/km, if distance > 0 | derived from distance + time |
| Avg Power | watts, if available | avg of `power` records |

- Cells show "—" when a field is not present in the activity
- Reference row distinguished by a left border in the reference highlight colour (see Theme)

## Theme

Implement dark and light themes using CSS custom properties (`--color-bg`, `--color-sidebar`, etc.). Apply `prefers-color-scheme` media query at the `:root`. No manual toggle in v1.

**ECharts canvas colour detection:** ECharts renders to `<canvas>` and cannot read CSS custom properties. Theme-dependent colours (segment bar tints, axis label colour, grid line colour, tooltip background) must be passed as explicit props to chart components. Each chart component reads the active theme at mount time using `window.matchMedia('(prefers-color-scheme: dark)').matches` and selects the correct hex values. Components also listen to the `change` event on that media query to re-render if the OS theme changes while the app is open.

### Dark palette (base)
- Page background: `#0f172a`
- Sidebar background: `#0a0f1a`
- Card background: `#0a0f1a`
- Border: `#1e293b`
- Primary text: `#e2e8f0`
- Muted text: `#475569`

### Light palette
- Page background: `#f8fafc`
- Sidebar background: `#f1f5f9`
- Card background: `#ffffff`
- Border: `#e2e8f0`
- Primary text: `#0f172a`
- Muted text: `#64748b`

### Accent colours (same in both themes)
- Device mode: `#3b82f6` (blue)
- Event mode: `#22c55e` (green)
- Reference highlight (Event mode sidebar row border + Summary row border): `#f59e0b` (amber) — this is **not** a file colour slot; it is reserved for the reference indicator only

### File colour palette (max 6 files; intentionally distinct from both mode accents and the amber reference indicator)

| Slot | Name | Hex |
|------|------|-----|
| 1 | Coral | `#f97316` |
| 2 | Sky | `#38bdf8` |
| 3 | Rose | `#f43f5e` |
| 4 | Violet | `#8b5cf6` |
| 5 | Teal | `#14b8a6` |
| 6 | Lime | `#84cc16` |

In Event Comparison mode the reference activity is **additionally** distinguished by a dashed line style, so colour alone does not need to encode "reference."

## Component Structure

```
src/
├── lib/
│   ├── components/
│   │   ├── ui/
│   │   │   ├── Sidebar.svelte           # Shell sidebar (mode nav, FileList, compact DropZone, footer)
│   │   │   │                            #   Renders DropZone compact=true directly below FileList
│   │   │   ├── FileList.svelte          # Colour-coded file list; reference badge in Event mode
│   │   │   │                            #   Does NOT contain DropZone — file drop is in Sidebar
│   │   │   ├── DropZone.svelte          # Reusable drop + file-picker
│   │   │   │                            #   Props: compact (bool)
│   │   │   │                            #   compact=false → full empty-state layout (used in +page.svelte)
│   │   │   │                            #   compact=true  → dashed button, no icon (used in Sidebar.svelte)
│   │   │   ├── ChannelToggleBar.svelte  # Channel pill toggles (shared by both modes)
│   │   │   │                            #   Props: channels (ChannelKey[]) — available pills,
│   │   │   │                            #     passed from parent (union of channels in activities)
│   │   │   │                            #   Reads session.activeChannels from the store to know
│   │   │   │                            #     which pills are active; writes session.activeChannels
│   │   │   │                            #     on toggle. Store is the source of truth so toggle
│   │   │   │                            #     state persists across tab switches.
│   │   │   ├── SmoothingSlider.svelte   # Smoothing control (present in both modes)
│   │   │   └── XAxisToggle.svelte       # Time / Distance pill toggle (present in both modes)
│   │   ├── charts/
│   │   │   ├── TimeSeriesChart.svelte   # ECharts line chart
│   │   │   │                            #   Props: series[], xAxisMode, referenceIndex?
│   │   │   │                            #   Line style rule (applied by array position, not semantics):
│   │   │   │                            #     if referenceIndex is undefined (Device mode):
│   │   │   │                            #       series[0] → solid; series[1..n] → [6,3] dash
│   │   │   │                            #     if referenceIndex is set (Event mode):
│   │   │   │                            #       series[referenceIndex] → [6,3] dash (reference = dashed)
│   │   │   │                            #       all other series → solid
│   │   │   │                            #   [6,3] = 6px dash, 3px gap
│   │   │   ├── DeltaChart.svelte        # Time delta line chart (Event mode)
│   │   │   ├── MeanMaxChart.svelte      # Mean/max power curve (Device mode)
│   │   │   └── SegmentChart.svelte      # Per-segment bar chart (Event mode)
│   │   └── map/
│   │       └── ActivityMap.svelte       # Leaflet map
│   │                                    #   Props: activities[], referenceIndex?
│   │                                    #   If referenceIndex undefined → all polylines solid
│   │                                    #   If referenceIndex set → ref polyline dashed, rest solid
│   └── stores/
│       └── session.ts                   # activities[], smoothing, xAxisMode,
│                                        #   referenceIndex (number), clearing (boolean),
│                                        #   lastMode ('compare'|'event'),
│                                        #   activeChannels (ChannelKey[])
└── routes/
    ├── +layout.svelte                   # Shell (sidebar + main slot)
    ├── +page.svelte                     # Landing / drop zone; reactive redirect to /compare
    ├── compare/
    │   └── +page.svelte                 # Device Comparison view
    └── event/
        └── +page.svelte                 # Event Comparison view
```

## Out of Scope for This Spec
